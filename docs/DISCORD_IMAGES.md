# Discord Image Assets

Dungeon Steward uses prepared local WebP assets for gameplay banners so the image can appear as a normal attachment in the same Discord message as the embed. The static Discord asset registry is still available for reusable CDN-backed thumbnails and other embed images.

## Standards

| Type | Use | Size | Preferred Format | Warning | Hard Limit |
| --- | --- | --- | --- | --- | --- |
| `thumbnail` | Items, potions, equipment, enemies, NPCs, discoveries, status effects, portraits | `256x256` | WebP, PNG allowed for transparency | 150 KB | 250 KB |
| `location_banner` | Steward's Hall, dungeon entrances, shops, inns, crypts, forests, ruins | `1200x300` | WebP | 500 KB | 750 KB |
| `encounter_artwork` | Optional future full encounter artwork | `1200x675` | WebP | 750 KB | 1 MB |

Keep important banner labels and symbols on the left half of the artwork; banner preparation preserves the left edge when cropping wide sources. Do not put small text in thumbnails.

## Files

```text
assets/
  discord/
    thumbnails/
      items/
      enemies/
      npcs/
      discoveries/
      status_effects/
    locations/
    encounters/
    source/
bot/content/
  image_assets.json
  image_asset_registry.json
```

`bot/content/image_assets.json` is the user-maintained catalog. Use stable logical keys such as `location.stewards_hall` or `item.potion.xp.01`.

`bot/content/image_asset_registry.json` is generated by synchronization. It stores Discord channel/message/attachment IDs, canonical CDN URLs, dimensions, file sizes and SHA-256 hashes. Do not add bot tokens or signed CDN query parameters.

`bot/content/emoji_assets.json` and `bot/content/emoji_asset_registry.json` do the same job for inline application emojis. Use these for tiny item markers that must appear inside embed field text, such as the potion icon before an inventory row. Discord cannot render arbitrary attached images inline in embed text, so the emoji registry must contain application emoji IDs before those markers appear.

## Environment

Set:

```env
DISCORD_ASSET_CHANNEL_ID=
```

The bot token remains secret. The asset channel ID is configuration. In production, run validation and sync before sending player-facing messages that require images.

## Discord Channel

Create a private channel visible only to maintainers and the bot. The bot needs:

- View Channel
- Send Messages
- Attach Files
- Read Message History

The sync script sends one labelled message per asset and attaches one image:

```text
Dungeon Steward static asset
Key: location.stewards_hall
Type: location_banner
SHA-256: ...
Dimensions: 1200x300
```

## Commands

Validate prepared local files:

```bash
python -m scripts.prepare_discord_assets --validate
```

Prepare files from `source_path` entries in the catalog. Source art is scaled and cropped to fill the target canvas; location banners preserve the left edge so labels and icons stay visible:

```bash
python -m scripts.prepare_discord_assets --prepare
```

Preview Discord synchronization:

```bash
python -m scripts.sync_discord_assets --dry-run
```

Sync all changed assets:

```bash
python -m scripts.sync_discord_assets
```

Sync one asset or prefix:

```bash
python -m scripts.sync_discord_assets --key location.stewards_hall
python -m scripts.sync_discord_assets --prefix item.potion
```

Sync inline application emojis:

```bash
python -m scripts.sync_application_emojis --dry-run --prefix item.potion
python -m scripts.sync_application_emojis --prefix item.potion
```

## Adding or Replacing an Image

1. Add the source artwork under `assets/discord/source/`.
2. Add or update the catalog entry in `bot/content/image_assets.json`.
3. Run `python -m scripts.prepare_discord_assets --prepare --key KEY`.
4. Run `python -m scripts.prepare_discord_assets --validate --key KEY`.
5. Run `python -m scripts.sync_discord_assets --key KEY`.
6. Commit the catalog, prepared asset and registry if the deployment flow commits generated registries.

Replacing an image changes its SHA-256 hash. The sync script uploads the changed file and updates the registry; unchanged hashes are skipped.

## Local Development

Gameplay banners are sent from prepared local files as message attachments. When no registry entry exists for thumbnails or other embed-only images in development, the runtime service can fall back to an `attachment://filename` URL for local testing. Optional missing images are omitted. Required production assets should be caught by validation and sync before deployment.

## Recovery

If an asset message is deleted, run sync for that key. The script does not delete old asset messages automatically and does not recreate assets from public Discord commands.

## Validation

The validators check:

- Catalog and registry JSON shape
- Duplicate keys
- Supported asset types
- Lowercase snake-case filenames
- Paths staying inside `assets/discord`
- Actual image format matching extension
- Exact dimensions
- Hard file-size limits
- Alt text
- Gameplay JSON references to known asset keys
- Registry hashes and dimensions against local files

Run the normal validation suite after image changes:

```bash
python -m scripts.validate_content
python validate_content.py
python -m pytest
```
